## Confirmed decisions

1. Hospital/clinic portal first. Platform-wide admin console and its global permissions are deferred.
2. Aggregate bed counts by facility and bed type first; no patient-to-bed allocation or admissions system in this slice.
3. Both independent drivers and operator-invited drivers. Independent registration creates an operator; joining an existing operator requires a verified invitation, never a client-supplied organization grant.
4. Figma establishes phone OTP for patient, doctor and driver. Hospital portal supports credentials and OTP; platform-admin email/password plus MFA is a later, distinct scope.
5. Bed types (General Ward, ICU, Private Room, NICU) must not be treated as medical departments (Cardiology, Neurology). These are separate dimensions.
6. Phone OTP is for sign-in/sign-up. A separate random four-digit patient PIN must verify ambulance-trip or home-visit **completion**. Earlier draft language that treats that PIN as a trip-start credential is superseded; the current trip-start schema needs reconciliation before that workflow is implemented.
7. Doctor and driver evidence will be manually reviewed; a separate company reviewer app is planned later. Current onboarding must remain pending and must not grant self-verification.

The earlier auth draft was moved to `drafts/auth-onboarding.unapproved.sql`. It is **not executable by db:migrate**, is not deployed, and must not be copied back without addressing the missing invitation, verification-document and profile flows. Installing SSR dependencies did not implement authentication.

## Fully Aligned

**No complete business workflow is connected end-to-end today.** Patient, doctor and driver operational screens still use demo/static/local state. The web bed screen now calls scoped RPCs, but that path awaits deployment, configuration and a provisioned member. Other web screens remain demos. Local filters/layout toggles work without database storage; this is correct client-only behavior, not business-workflow alignment.

Do not confuse these distinctions: (1) Figma requirement, (2) rendered demo screen, (3) schema foundation, (4) deployed API, (5) app integration, (6) tested cross-app workflow.

| Ambulance → handoff → payment        | Patient timers, driver local state                         | Booking/offer acceptance transaction               | eligible shift → unique assignment → tracking → arrival → patient completion PIN or exception → handover → final quote → receipt event | Two drivers race; stale GPS; completion PIN lockout; guest exception; payment not inferred |
| Hospital beds                        | Local +/- counts                                           | Scoped inventory API                               | facility membership → version check+count invariant → audit/event → patient/operator freshness display                    | Cross-facility denial; concurrent edits; no negative/overcapacity counts             |
| Onboarding                           | Figma forms / driver demo                                  | OTP/session and verified identity linkage          | self declaration → private evidence → authorized review/invitation → role-specific app access                             | No self-verification; no arbitrary tenant join; revoked/disabled identity denied     |

For each command, write state+audit+outbox in one transaction; publish only after commit. Realtime is a notification/projection channel, not a second source of truth. Reconnect performs an authorized refetch; keys include identity/facility/patient/trip scope. Do not notify external parties during development tests.

## Open decisions and implementation order

Changes made after the review:

- Added local Drizzle bed_type/facility_bed_inventory models and 20260923045204_aggregate_bed_inventory.sql. RLS stays default-deny; counts cannot be negative or exceed total; ownership is immutable and updates preserve version/timestamp guards. **Not deployed or exposed by an API.** Applied migrations were not edited.
- Corrected the web demo invariant: available + occupied + maintenance = total. Maintenance beds cannot become available through +/- controls. The maintenance card derives its count/percentage from rows; labels say bed type. The General Ward fixture explicitly owns the 7 demo maintenance beds so totals reconcile. These are not live values.
- Added client-safe canonical state and proposed ID-based booking/inventory types. Types are not runtime validation or implemented endpoints.
- Created PROJECT_CONTEXT.md, evidence/ownership/action/reverse matrices and ER/application diagrams. These architecture updates follow the user's explicit request beyond the audit skill's normal read-only scope.
- Quarantined the guessed auth migration, which omitted operator invitations and verification evidence.

These close specific schema/documentation/demo arithmetic gaps. They do **not** close authentication, inventory APIs, booking or any full business-workflow gap.
