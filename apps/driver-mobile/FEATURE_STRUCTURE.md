# Driver feature ownership review

Reviewed all 38 original source files under `src/features` and their callers.
This is a structural refactor of the existing flows. Deployment and device
verification remain separate.

## Conventions

- `screens/`: navigable composition and presentation.
- `components/`: feature UI, including private presentation state and animations.
- `hooks/`: queries, mutations, subscriptions, device effects and flow coordination.
- `types/`: named feature contracts, with kebab-case filenames.
- `utils/`: pure helpers and flow-owned `*Constants.ts` display configuration.
- `services/`: platform integrations and persistence with side effects.
- `stores/`: navigation drafts shared by screens.

Create a folder with its first implementation. Small private presentation helpers,
one-off literals and state-dependent collections can stay local. Styles stay with
their UI owner. Shared domain rules and operations remain in the shared packages.

## Boundaries preserved

- Registration/profile queries and state move into hooks without changing gates,
  form inputs or submission arguments. `RegistrationScreens.tsx` retains its
  existing compatibility exports.
- Registration and saved-location pickers retain separate hooks and draft stores,
  their original map camera effects, and their different confirmation routes.
  Pure map helpers and map styles remain shared within the locations feature.
- Existing home/offer and trip controllers remain the owners of expiry timers,
  availability, PIN checks and trip actions. Chat coordination and earnings
  filtering have their own hooks; static replies/periods stay in constants files.
- `DriverLocationReporter` remains mounted at the existing app boundary. Its hook
  retains the shift dependency, stream epoch/sequence, watch subscription, sample
  timer and cleanup. Background task definition stays at module scope in
  `tracking/services/backgroundLocationTask.ts`, imported by the root layout.
  The task name and background update payload are unchanged.
- The notification service initializes the Expo SDK once; the existing listener
  hook stays at its original layout call site.

## Verification

- 16 local tests pass, including stores, live offers/trips, distinct map picker
  payloads/routes, structure checks and foreground tracking cleanup. Tracking tests
  cover unmount, a late watcher, background suppression and an offline driver.
- Typecheck still reports the same 63 baseline diagnostics; no added diagnostic
  codes/messages. Existing dependency/auth typing failures remain unresolved.
- Compared 29 route-module bodies and 7 StyleSheet definitions with the starting
  snapshot: unchanged. All 9 extracted controller prefixes retain their original
  statements. No runtime import cycles were found in feature modules.
- Foreground/background permissions, OS task delivery, device location, push
  delivery and native navigation still need device verification.
