# Company Admin source ownership review

Reviewed all 19 original TypeScript source files, their callers, tests and
empty scaffolds. This organizes existing functionality; it does not change schemas,
dependencies, URLs, UI copy or workflow rules.

## Conventions

- `src/app`: URL parameters, route adapters, layouts and HTTP handlers.
- Feature `screens`: screen composition and presentation.
- Feature `components`: UI sections and controls, including local presentation state.
- Feature `hooks`: form/query/mutation coordination, subscriptions and lifecycle.
- Feature `types`: named UI and workflow contracts.
- Feature `utils`: pure helpers and `*Constants.ts` display configuration.
- Feature `services`: browser/platform integration and client persistence.
- Feature `server`: authorized server queries and Server Actions.
- `tests/unit`: regression checks outside runtime feature modules.

Create a folder with its first implementation. Small private presentation helpers,
one-off literals and state-derived values can remain local. Generic primitives
continue to come from `@startup/web-ui`; app workflows stay in their owning app.

## Boundaries preserved

- Login, verification overview, queue and case detail now have feature screen
  owners. The original route URLs, async parameters, filtering, keyed table resets
  and rendered content are preserved through public feature route adapters.
- Reviewer query loaders retain the original authorization, query order and
  not-found handling. They are guarded server-only modules and are never imported
  through a client-consumed barrel.
- Review/finalize actions moved from the route directory into verification server
  ownership. They keep reviewer checks, input validation, RPC arguments, driver date
  handling, automatic doctor finalization and revalidation paths.
- Document actions, finalization and their fields have individual UI owners. Action
  state and review feedback live in hooks; each form retains its binding parameters,
  pending behavior and toast/refresh lifecycle.
- Table column renderers stay with table presentation. Status labels/styles,
  document labels, URL filter choices and shell navigation have static owners.
  State-dependent metrics and document requirements remain computed locally.
- Authentication actions have an auth server owner. Reviewer guards and the
  request-scoped Supabase/cookie clients remain app-level server integrations.
- Architecture tooling and TypeScript test-loader helpers are reused from Facility
  Portal's scripts. No application runtime code imports another web app.

## Verification

- 7 local tests pass: source boundaries, denied reviewer reads, queue filter
  fallbacks, solo-clinic document requirements, review/finalize action arguments,
  revalidation, failed actions and deduplicated review feedback.
- All 4 extracted controller prefixes and 3 server query prefixes retain their
  original executable statements. All 98 static styling class attributes match
  the starting source snapshot.
- Architecture and feature checks pass, including runtime import cycles and
  transitive client/server boundaries.
- Route type generation, standalone TypeScript checking and production builds pass
  outside the Windows sandbox. Sandboxed checks reported the same 45 diagnostics
  before/after; those diagnostics did not reproduce in the unrestricted checks.
- Lint retains the existing unescaped apostrophe in verification copy. Reviewer
  browser sessions, document upload/review and deployed authorization still need
  browser/integration validation.
