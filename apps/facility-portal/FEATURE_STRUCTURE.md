# Facility Portal source ownership review

Reviewed all 99 original TypeScript source files, their callers, tests and
empty scaffolds. This organizes existing functionality; it does not change schemas,
dependencies, URLs, UI copy or workflow rules.

## Conventions

- `src/app`: URL parameters, route adapters, layouts and HTTP handlers.
- Feature `screens`: screen composition and presentation.
- Feature `components`: UI sections and controls, including local presentation state.
- Feature `hooks`: form/query/mutation coordination, subscriptions and lifecycle.
- Feature `types`: named UI and workflow contracts.
- Feature `utils`: pure helpers and `*Constants.ts` display configuration.
- Feature `services`: browser/platform integration and client persistence.
- Feature `server`: authorized server queries and Server Actions.
- `tests/unit`: regression checks outside runtime feature modules.

Create a folder with its first implementation. Small private presentation helpers,
one-off literals and state-derived values can remain local. Generic primitives
continue to come from `@startup/web-ui`; app workflows stay in their owning app.

## Boundaries preserved

- Appointment filtering, pagination, review transitions and QR/camera coordination
  stay in one appointments hook. Request and mutation arguments, camera cleanup,
  server actions and refresh behavior are unchanged. Walk-in booking keeps its
  loading states, request sequencing and confirmation arguments.
- Login, logout, signup, appointment acceptance and facility live updates retain
  their original action state, effects, event scopes and cleanup.
- The doctor API owns its existing HTTP request/parsing operation. Directory hooks
  retain query keys, abort signals, filters and cache behavior. Association event
  subscriptions remain mounted at their existing component boundaries.
- The schedule service picker and keyed editor remain separate. The editor still
  uses the practice/consultation-type key. Numeric inputs keep their own focus/draft
  state, while the schedule hook retains duration suggestions, explicit effective
  date, publication arguments and cache updates. Leave actions have the same
  validation and practice-scoped invalidation.
- Facility registration/verification state mounts once. Its address section receives
  existing values/callbacks. Browser geolocation and the singleton map SDK loader
  have service owners; map listeners and late-load cleanup stay in the map hook.
- Bed management retains independent row saves, version conflicts and reconciliation.
  Its row-color helper is separated from static color configuration.
- The route composes the logout slot into the shared shell. The shell has no feature
  imports. The bed HTTP handler uses the explicit guarded facilities server entry;
  the client-consumed feature index does not export server operations.
- Obsolete empty dashboard/server/dispatch/staff markers and empty source directories
  were removed. Future dispatch, staff and observability work stays in architecture
  documentation. The schedule regression test moved to `tests/unit`.

## Verification

- 35 local tests pass, including architecture, schedules, bed saves/conflicts,
  association events, map cleanup, live update coalescing and late camera cleanup.
- All 18 extracted controller prefixes retain their original executable statements.
  All 766 static styling class attributes match the starting source snapshot.
- Structure checks cover imports, syntax, named type ownership, runtime cycles and
  transitive client/server boundaries. Architecture checks now pass; both original
  import-boundary violations were resolved through composition/public server entry.
- Route type generation, standalone TypeScript checking and production builds pass
  outside the Windows sandbox. Sandboxed checks reported the same 74 diagnostics
  before/after; those diagnostics did not reproduce in the unrestricted checks.
- Lint retains existing findings in the bed stepper, CommonJS test imports and an
  unused auth action parameter. Browser permissions, camera scanning, maps,
  subscriptions and deployed authorization still need browser/integration validation.
