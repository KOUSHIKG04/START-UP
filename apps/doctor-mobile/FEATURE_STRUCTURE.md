# Doctor feature ownership review

Reviewed all 67 original source files under `src/features` and their callers.
This is a structural refactor of the existing flows. Deployment and device
verification remain separate.

## Conventions

- `screens/`: navigable composition and presentation.
- `components/`: feature UI, including private presentation state and animations.
- `hooks/`: queries, mutations, subscriptions, device effects and flow coordination.
- `types/`: named feature contracts, with kebab-case filenames.
- `utils/`: pure helpers and flow-owned `*Constants.ts` display configuration.
- `services/`: platform integrations and persistence with side effects.
- `stores/`: navigation drafts shared by screens.

Create a folder with its first implementation. Small private presentation helpers,
one-off literals and state-dependent collections can stay local. Styles stay with
their UI owner. Shared domain rules and operations remain in the shared packages.

## Boundaries preserved

- Appointment review, request expiry and QR redemption keep their existing query
  keys, mutation arguments, navigation and refresh behavior.
- `ConsultationForm` loads the draft through `useConsultationDraft`. The separately
  owned `ConsultationWizard` keeps its appointment key and existing
  `useConsultationForm` state. Vitals, prescription and follow-up retain their
  original steps and submission behavior.
- Online consultations keep separate demo/live components. LiveKit global
  registration stays at module scope in the screen module; call audio lifecycle
  and message subscriptions retain their existing mount boundaries.
- Schedule components render the existing sections. The editor and unavailable-time
  controllers own practice persistence, queries, cache updates and actions.
  `initialSchedule` remains a factory in `utils/scheduleDefaults.ts` so each draft
  receives its own values; static UI lists live in constants modules.
- Location draft stores stay separate from the geocoding/device services. Address
  requests retain their queue, deduplication and cancellation behavior.
- The notification service initializes the Expo SDK once. Its hook owns the
  existing listeners and cleanup; the app layout calls it once as before.
- `ScheduleOperationsPanels.tsx` and `OnboardingShell.tsx` preserve established
  component exports while active callers import the specific component owners.

## Verification

- 58 local test cases pass, including updated QR, consultation, schedule, address
  and feature-ownership checks. Legacy schedule tests now exercise the actual
  schedule screen rather than the removed `PublishSessionPanel`.
- Typecheck still reports the same 95 baseline diagnostics; no added diagnostic
  codes/messages. Existing dependency/auth typing failures remain unresolved.
- Compared 37 route-module bodies and 22 StyleSheet definitions with the starting
  snapshot: unchanged. All 26 extracted controller prefixes retain their original
  statements. No runtime import cycles were found in feature modules.
- QR/camera, LiveKit, permissions, push delivery and native navigation still need
  device verification. Mocked tests do not establish those behaviors.
